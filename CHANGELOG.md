# Changelog

All notable changes to LEVI. Versions follow the tags on GitHub; everything under **Unreleased** is on `main` but not yet in a tagged release.

## Unreleased

### Live annotation

- **`levi live`: a background LEVI that labels robot rollouts while an evaluation writes them.** `start [--daemon] [--auto-approve]`, `stop`, `status`, `doctor`, `once [--fake-vlm]`, `init`; one TOML file (`live.toml`, every default listed, unknown keys are errors). A stdlib-only supervisor (idle: about 30 MiB, one thread, 0.09 % CPU, stat-only scans) mirrors finished rollouts (`.complete` plus the metadata rules; half-written, `incomplete_*` and `discarded_*` ignored, backlog skipped) by hard link into its own workspace, asks a GPU policy whether the local model may work, and starts one worker process per dataset batch: temporal run with the generic guideline quoting the task instruction, commit, then one release-review run whose verdict is an anchored-review record, never a human outcome label. Resumable at every step; datasets one at a time. `timeshare` (default) keeps the policy server (`XLA_PYTHON_CLIENT_MEM_FRACTION=.22`) and vLLM (`0.74`, `--enable-sleep-mode`) resident and gates the model's work around episodes (a new episode cancels the in-flight request and the run backs off; vLLM sleeps when its memory is wanted and wakes in under a second); `coexist` and `manual` are manual choices. Everything it starts runs at nice 19, ionice idle, bounded threads; logs rotate, caches are capped, `status.json` and the API are bounded. Read-only `/api/levi/live/{status,sessions,datasets,datasets/<name>,audit}`. See [Live annotation service](docs/LIVE.md).
- **`levi live` no longer cold-starts vLLM during an evaluation, budgets from the policy server's held memory, and says why it is not labelling.** A cold start waits for standby/finished sessions (`--prewarm` / `vllm.prewarm` brings the model up in advance and keeps it resident); a wake needs an open gate; a person's Run/Resume in the page is refused (409) while the policy infers; the default vLLM budget is `0.74` (0.72 does not serve 49152 tokens once the compile cache is warm) and a KV-cache failure names the budget to use; a listening policy port that holds little VRAM is "still loading"; `status.json` gains `labelling_paused` and `loop_at` (the doctor warns when the loop stops), sessions use the client's `waiting_reset_since`; a wait for a person survives a restart; an audit record that cannot be written is a counted warning. See [Live annotation service](docs/LIVE.md).
- **An explicit, audited automatic approver.** `Principal.auto` (`live-auto`) exists only in a workspace with `live/workspace.json`, only with `LEVI_LIVE_AUTO_APPROVE=1` (given to the live worker by `--auto-approve`), only for a short list of calls and only on runs it planned itself. Its approvals carry `reviewer_type: auto`, the segments it commits `levi.review: auto` (a person saving different text marks them `edited`), every call goes to `live/audit.jsonl`. Approving and committing stay human-only everywhere else.
- **Fixed: pausing a run did not cut the model requests of episodes processed in parallel** (`requests_in_flight` > 1): the pool threads lacked the run's request context, so the pause waited for the slowest request.
- **Fixed: an unattended rollout's placeholder `success_flag_final = 0` read as a recorded failure** (`eval.outcome` `unlabeled` or `aborted` now means no robot label).

- **A live page (`/live`).** Read-only view of evaluation sessions, the FR3 arm (red banner on a red light or a session in `fault`; a missing monitor is not a red light), the annotation pipeline (automatic results drawn as unreviewed) and the service's GPU gate in plain words; polls every 2 s while an evaluation runs, 10 s otherwise, pauses when hidden, backs off on failure. The sessions API now also reports the policy config, the checkpoint folder name, the reset wait and the start time. The page also shows what needs a person (`attention` with a copyable `levi live resume`, datasets awaiting approval, a page or core that did not start), the reset countdown, the number of open review runs, and explains every GPU gate and decision code; the top navigation wraps on a phone instead of hiding entries. See [Live annotation service](docs/LIVE.md#the-live-page).

### Training pool

- **Pool jobs survive being stopped: resume, states, heartbeat, errors, cleanup, deleting jobs.** A user's 12-minute RECAP export was lost when a product restart (`levi stop` SIGTERMs its workers, exit 143) killed it at 895 of 974 units, the page kept showing the last progress and the partial output was deleted. Now the worker owns its job record and writes the final state itself; states are `planned`, `running`, `stalled`, `cancelling`, `cancelled`, `interrupted`, `failed`, `done`, `done_with_errors` (records that say `succeeded` read as `done`); a heartbeat every 2 s gives `age_seconds`, and a dead worker is reported `interrupted` on the next poll. An export keeps its `.partial` folder and a durable journal (`resume.json`, `resume.units.jsonl`: per finished unit the size and sha256 of its files) when it is stopped, killed or crashes, and `levi pool export --resume <job>`, `POST /api/levi/pool/jobs/{id}/resume` and the page's **Resume** verify the frozen plan (hash, unchanged sources, held-out lists) and every finished unit on disk, redo what fails, and finish with the same result as an uninterrupted run; **Re-run** plans again from the saved recipe; an explicit **Cancel** still removes the partial, a stop or kill keeps it; raw-capture copies, pushes (rsync `--partial`) and scans resume too, `LEVI_POOL_AUTO_RESUME=1` resumes exports at service start. `levi stop` refuses while pool, conversion, RECAP or segmentation jobs run (`--wait [minutes]`, `--force`; the core stop route answers 409 unless `force`). Each job has one timestamped `<id>.log` and an `errors.jsonl`; a failing episode is left out (`convert_error`) and the export continues (`done_with_errors`) until more than `on_error_max_fraction` (default 0.1) fail; fatal errors write a structured `error.json` with a hint (exit codes 143/137, disk full, permission, missing source, held-out refusal); the page shows a state chip, "last update N s ago", a banner with Resume / Re-run / Cancel / View log / Copy error report and adapts its polling; exports refuse early with numbers when the volume cannot hold them; a resample export below the export fps is refused before conversion; `pool_export.json` records `errors`, `resumed`, `resumes`, `interruptions`, `job_id`. A sweeper (`levi pool clean`, `levi clean`, the page's **Cleanup** section, at service start and after each job) removes finished-job partials at once and expired ones after `LEVI_POOL_PARTIAL_TTL`, job files after `LEVI_POOL_JOB_TTL`. The recent-jobs list can **Clear record** and **Delete record and files** (one, several, or all failed and interrupted; `levi pool jobs delete|clear-failed`, `DELETE /api/levi/pool/jobs/{id}`): only the job that produced a directory deletes it, only inside the export roots, never a source, a symlink or a running job's output, a changed folder needs a second confirmation, and every removal is logged in `pool/deleted.jsonl`. See [Training pool](docs/TRAINING_POOL.md#jobs-states-resume-errors-cleanup--作业状态续做错误清理).
- **Timing mode for LeRobot and RECAP exports, and warnings when a rollout runs slower than the export fps.** Rollouts are recorded at about 9.5 fps (online RL) to 9.96 fps while exports default to 10 fps. The export panel now has a **Timing** select (Resample: drop frames only, refused below the export fps; Retime: keep every frame and declare it at the export fps, so the time axis stretches or shrinks slightly), the same `timing` option exists in the API and as `levi pool export --timing`, defaults stay per format (LeRobot resample, RECAP retime) and a raw capture copy ignores it. The index (a rescan adds it) keeps each raw episode's measured rate (`measured_fps`); the preview (`POST /api/levi/pool/preview` with `fps`/`timing`, `levi pool recipe show --fps --timing`, the composition panel) reports `source_fps_below_export` with the counts and the fixes (lower fps to the nearest integer below the slowest rate, or Retime; the export panel blocks the case that would certainly be refused) and, for Retime, an informational `retime_time_scale` note with the largest time-axis deviation. A resample export below the export fps is now refused before conversion starts, with the suggested fps. `pool_export.json` records `timing` (mode used, source fps range, time-scale range) and, per episode, `source_fps` and `time_scale`. See [Training pool](docs/TRAINING_POOL.md#frame-rates--帧率).
- **How many episodes each task contributes, and a smart pick of which.** A recipe's task list now holds entries `{task, count, success_ratio, strategy}` (`quality`, `random`, `first`); the global `per_task_cap` stays as the fallback for entries without a count, and saved recipes with a plain task list load as before (`strategy: random`, the same seeded draw). For a task with hundreds of episodes the Training pool page opens a chooser on **+ Add** (number of episodes, defaulting to the median of the tasks already added and 100 for the first; share of successes: natural, all successes, all failures or custom; smart pick, random or in order) and each composition row shows *Picked N of M · successes · failures*, can be edited and lists the picked episodes with their quality score and reason. The smart pick (`levi/pool/select.py`) splits a task's episodes by the export's outcome (human label, then the robot's flag), fills the success/failure quota (a short side is topped up from the other and reported), ranks episodes by label trust, completeness against the task's median length and, for successes, efficiency (failures: enough length for an attempt), breaks near-ties with RECAP advantage labels when a scanned LEVI workspace holds them, and spreads the picks over policy method, checkpoint, source and month; episodes already picked for an earlier task are skipped. Selection is deterministic for a recipe, seed and index, and preview, plan and export share one function; the preview reports per-task available/selected/shortfall and the overall mix, and `pool_export.json` records each episode's stratum, quality score, reason, outcome and outcome source plus per-task requested and achieved counts. New `POST /api/levi/pool/selection` and `/suggest`, `levi pool recipe save --task "text:count=50,success=0.6,strategy=quality"`, `levi pool recipe episodes|suggest`. See [Training pool](docs/TRAINING_POOL.md).
- **Which policy produced a rollout, and how it was run.** The pool's single `policy` column (the checkpoint name) hid whether a rollout came from a direct deployment, an online-RL run (DSRL, RLT, SFE) or a student policy. The index (schema `levi.pool.index.v2`, an older index asks for a rescan) has `policy_model`, `policy_checkpoint`, `policy_method` (`direct`, `dsrl`, `rlt`, `sfe`, `student`, `other`, `unknown`), `policy_phase` and a readable `policy_label`, read from `policy.config`, `policy.checkpoint_dir`, `policy.method`, `method`, `control_mode` and the folder layout; LeRobot rollouts inherit them from their linked raw capture, then `rollout_source_method` and `rollout_source_demo`. Recipes, `levi pool episodes|tasks|recipe save` (`--policy-model`, `--policy-checkpoint`, `--policy-method`), the tasks/episodes API and the facets accept the three filters next to the old `policies`, which keeps meaning the checkpoint; facets return counts for each, tasks carry their methods, previews count models and methods, and `pool_export.json` records the fields per episode. The Training pool page replaces its Policy facet with Policy model, Checkpoint and How it was run (only when the selection holds rollouts), and adds the policy label to the episode table and the methods to the task table. See [Training pool](docs/TRAINING_POOL.md).
- **Every dataset on the machine in one per-episode index, composed into new training sets.** `LEVI_POOL_ROOTS` names read-only folders; `levi pool scan` (API `POST /api/levi/pool/scan`, a tracked worker with progress) finds raw captures, LeRobot v2.x and DROID raw and lists pickle/npz/npy folders as unsupported sources, classifies each episode as human, rollout, LEVI output, external or archive from its metadata and data-driven rules, normalises task text (case and underscores), flags non-standard demo folders, groups byte copies, filtered variants and conversions of one recording (canonical: the original folder), joins human outcome labels from every LEVI workspace under the roots and the robot's flag, and marks held-out episodes from `LEVI_POOL_HELDOUT` lists by path and video sha256, copies included. Recipes (`levi pool recipe save|show`, `/api/levi/pool/recipes`) select categories, sources, an ordered task list, outcome (`all`, `robot_flag_success`, `verified_success`), dates, policies and a per-task cap; `levi pool export` (`POST /api/levi/pool/export`) writes a merged LeRobot v2.1 dataset (task order, unified camera keys and fps, refusal on state/action or resolution mismatch), a RECAP value dataset or a raw-capture copy into `LEVI_EXPORT_ROOTS`, with `pool_export.json`. Held-out episodes are refused, not filtered.
- **A Training pool page and remote transfer.** `/pool` (navigation and a Workbench card): scan status with progress, facets (category, source, task search, outcome, policy, date; held-out, copies and archive hidden by default with their counts), task and episode tables linking to the viewer, a composition panel (drag or up/down reordering, per-task cap, seed, live preview with each exclusion reason, named recipes) and an export panel (format, name, directory checked against `LEVI_EXPORT_ROOTS`, fps, cameras, hard links, dry run, progress). Held-out episodes cannot be selected. `levi pool remote add|list|delete`, `levi pool push <export> --target <name> [--dry-run]` and `POST /api/levi/pool/push` send a finished pool export with rsync over SSH (keys only, `BatchMode`, strict host keys, argument lists, resumable, progress, cancel, tracked child); new routes `facets`, `jobs/{id}/cancel`, `jobs/{id}/summary`, `remotes`, `push`, and `PUT` is proxied by the UI. See [Training pool](docs/TRAINING_POOL.md).
- **Training pool hardening from the independent review.** Exports are refused without `LEVI_POOL_HELDOUT` (or an explicit `none`) and when the held-out lists differ from the scan's; unmatched held-out entries warn. A raw-capture export lying in a pool root is classified as LEVI output and never becomes the canonical copy. A task taken from raw captures and from an unlinked LeRobot dataset is refused unless sources are named (`allow_unlinked_sources`). Task texts `.`/`..` can no longer write outside the staging folder, and every write path is checked. `--hardlink` links videos only. Conflicting human labels leave verified outcomes and RECAP exports (`label_conflict`); new `human_verified_success` outcome; the preview counts outcome sources. RECAP exports can count human demonstrations as successes (`human_as_success`). `pool_export.json` records the effective conversion, each episode's group and the held-out setting; state names, camera maps and duplicate task texts are checked; dry runs leave no plan; a cancelled or stopped export removes its `.partial` folder. Tests snapshot the source datasets before and after every export format.

### Report page

- **A live technical report inside LEVI.** `/report` (top navigation) renders a report kept in a folder you name with `LEVI_REPORT_DIR`: `LEVI.md` and `LEVI.zh-CN.md` for the text (the page follows the language switch and falls back to English), `status.json` for live data, `assets/` for images. The folder is read-only and may lie outside the workspace. Fenced `levi-progress`, `levi-chart`, `levi-metrics`, `levi-table` and `levi-timeline` blocks become components; a broken block shows its error in place. The page checks for a change every 5 s and swaps a changed report in without moving the scroll position. `GET /api/levi/report` (document, ETag/304), `GET /api/levi/report/version` (a change marker from file stats only) and `GET /api/levi/report/assets/{path}` (images under `assets/` only, SVG sandboxed). See [API](docs/API.md#technical-report--技术报告).

### Fast instance segmentation

- **A live segmentation overlay while an episode plays, and fast dataset labelling.** A student model distilled from SAM3 (RF-DETR-Seg, Apache-2.0, FP16) with ByteTrack (MIT) runs in its own environment (`integrations/segmentation`, `setup.sh`). In the episode viewer (Annotations → Objects → Fast segmentation) a live session follows the player clock on both cameras; each camera's overlay draws the frame on screen, or the newest result no more than 3 frames old, and never waits for the model. Instance ids and concept labels stay stable across frames (per-track concept vote). Stopping saves the frames shown as one revision for that episode. Offline labelling runs the student (fast) or the SAM3 worker (quality) over chosen episodes with progress and cancel. **Distil a student** chains SAM3 pseudo-labels, RF-DETR training and held-out scoring against the teacher into one GPU-locked job and registers `checkpoints/segmentation/<name>/` with a manifest (concepts, teacher, episodes per split and source dataset, held-out AP50/AP/recall, tracker settings, licences). Routes `segmentation/status|models|label|distil|jobs|live` (live clock, server-sent events, stop), read-only agent capability `segmentation.status`. Settings: `LEVI_SEG_WORKER_PYTHON`, `LEVI_SEG_MODEL_DIR`, `LEVI_GPU_LOCK_FILE`, `LEVI_GPU_LOCK_TIMEOUT_SECONDS`, `LEVI_SEG_MIN_FREE_MIB`, `LEVI_SEG_DISTIL_MIN_FREE_MIB`, `LEVI_SEG_LIVE_MIN_FREE_MIB`, `LEVI_SEG_LIVE_MAX_SESSIONS`, `LEVI_SEG_LIVE_IDLE_SECONDS`, `LEVI_SEG_TIMEOUT_SECONDS`, `LEVI_SEG_STALL_SECONDS`. See [Fast segmentation](docs/SEGMENTATION.md).
- **Fixed: a SAM3 run erased the other episodes' objects.** Publishing replaced the whole object sidecar; runs now replace only the (episode, camera) pairs they covered (`SidecarStore.publish_merged`, unchanged mask files hard-linked).
- **Fixed: SAM3 propagated only the last text prompt.** SAM3's `add_prompt` resets the session, so earlier prompts kept only their first-frame result; each prompt is now added and propagated on its own in the same session (the video loads once), with track ids offset per prompt.

### Training manifests

- **A hand-off to a fixed training recipe.** `levi export manifest <dataset> --operation …` (API `POST /api/levi/manifest`) writes `frames.parquet` (per frame: include, weight, the reason for an exclusion, the episode verdict and its source, the active annotation's subtask and outcome, RECAP value/advantage/label) and `manifest.json` (LEVI commit, dataset content fingerprint, namespace, annotation revision, anchored run and spec, RECAP revision/checkpoint/threshold, operation and parameters). Built-in task-generic operations `all_rollouts`, `robot_flag_success`, `verified_success` (human label > anchored review for the tasks it is valid for > robot flag), `advantage_positive_mask`, `advantage_weighted`; `levi export diff` gives the input difference between two manifests. A standalone reader for trainers (`integrations/training_manifest/levi_manifest_reader.py`: episode filter, weighted sampling, per-action-step mask, RECAP CFG prompt, draw audit). See [Training manifests](docs/TRAINING_MANIFEST.md).

### Anchored review

- **One narrow question at every recorded robot event (release-anchored review).** A review plan with `workflow.anchored` (a built-in spec id or a whole spec, frozen by the plan) finds the episode's gripper openings (or closings) in its declared state/action gripper dimension — a raw capture's view records the gripper command, so anchors are the command's transitions to the frame — and at each one sends a local model the spec's frames per camera at fixed offsets (native PNG) and its question, decoded against its ordered enum fields with no system prompt (`LocalProvider.ask`). A rule marks each event valid, contradicted or unknown (per condition too), a rule over the valid events gives the outcome, and the outcome is one `outcome` proposal in the review queue citing the frames nearest the events. Per-event records per run (`anchored` records, `episode_NNNNNN-anchored.json`); each question is budgeted, cached, metered and set aside like a model phase. Read-only capabilities `anchored.specs` and `anchored.get`, routes `anchored/summary` and `anchored/episodes/{N}`, and an ANCHORED REVIEW row in the annotations timeline (markers coloured by verdict, the answers on hover). Built-in spec *Plates release-review rules* (`plates-release`; the former id `plates-release-ar2` still resolves) reproduces the accepted external release-anchored review of the plates task frame for frame. Specs carry a per-language `title`, which the timeline row, `anchored.get` and the outcome proposal show instead of the id. See [Anchored review](docs/ANCHORED_REVIEW.md).
- **Start check and vetoes, declared in the spec.** A spec may add `start` (one question per episode on frames at its start or end, whose answer waives required labels) and `vetoes` (rules any event can break, each read from the event's answer or asked as its own question, failing the episode or only its event); views of the start check and of a veto may sit `at` the episode's `start` or `end`, the spec's own views stay at the anchor. Records keep the start answer, each waiver's reading and every veto's verdict (`confirmed`, `cleared`, `undecided`, `not_asked`); `basis` gains `waived_labels` (waivers the outcome rests on), `redundant_waivers`, `contested_waivers` (waived, but the label's own events are not valid), `vetoes` and `undecided_vetoes`. A success resting on an undecided veto or a contested waiver is undecided: named in the proposal's `uncertainty`, and `anchored_undecided` in training manifests; `verified_success` leaves such a success out by default (parameter `undecided`, `exclude` or `include`). Citations include the confirmed veto's own frames and, when a waiver decided the outcome, the start frame. With a start check a plan's `minimum_requests` is one per episode. Specs without these fields freeze, ask, record and decide exactly as before (byte-for-byte regression tests). Not yet in the viewer: the timeline row shows neither the start check nor veto verdicts.
- **Spec `status`.** `stable` (default) or `candidate`; `anchored.specs` lists stable specs first with their status, and a plan records `anchored_spec.status`. Candidate *Plates release-review rules, rule set 3* (`plates-release-3`: rule set 2 plus a start check), validated on development data only, is never a default.

### RECAP value model and advantage labels

- **Per-frame values and advantage labels from a RECAP value model.** A checkpoint store `checkpoints/recap_value/<name>/` with a `manifest.json` for every choice the model needs (expert variant, camera views, base models and tokenizer, return range, threshold); `levi recap import|set|checkpoints|run|show`. A job runs RLinf's `ValueCriticModel` in its own environment (`integrations/recap_value`, `setup.sh` applies openpi's transformers patch; `--selftest` checks the build without a checkpoint) or a `fake` provider without a model, then LEVI computes RLinf's N-step advantage and labels each frame against the request's threshold, the checkpoint's unified threshold or this dataset's quantile. Revisions per dataset (namespaces separate) under `workbench/recap_values/<name>/`, with RLinf's `advantages.parquet` columns, provenance and a stale flag; routes `recap/status|run|jobs|summary|episodes`, read-only agent capabilities `recap.status` and `recap.get`. Settings: `LEVI_RECAP_VALUE_CHECKPOINT_DIR`, `LEVI_RECAP_VALUE_WORKER_PYTHON`, `LEVI_RECAP_VALUE_MIN_FREE_MIB`, `LEVI_RECAP_VALUE_TIMEOUT_SECONDS`, `LEVI_RECAP_VALUE_STALL_SECONDS`, `LEVI_RECAP_VALUE_BATCH_SIZE`, `LEVI_RECAP_VALUE_DEVICE`. See [RECAP](docs/RECAP.md#value-model-and-advantage-labels-in-levi--levi-中的价值模型与优势标签).

- **RECAP follow-ups.** `levi recap import --preset fr3_recap` fills every field of the FR3 RECAP run; a checkpoint whose views or `model_type` contradict the preset, or whose expert variant contradicts its weights, is not ready. `levi recap inspect <name>` builds the model on the CPU and loads the weights strictly, reporting missing and unexpected keys. Shared base models live in `checkpoints/recap_value/_base/<name>/` (`levi recap base import|list`); every file is checked against the official Hub release (git blob id or LFS sha256) or a shipped `sha256` list, and a folder that is not fully verified is marked development-only in the revision and the timeline. `levi recap threshold <repo_id>…` computes RLinf's unified threshold over several datasets and can store it on a checkpoint with its provenance. A checkpoint whose manifest names the training data's static-frame filter (`static_filter`, `levi recap run --static-filter auto|on|off`) labels a raw-capture view over the kept frames only; the dropped frames stay unlabelled. The summary and per-episode label routes accept `optional=true` and answer 200 with `null` instead of 404 when a dataset has no labels yet, so the viewer no longer logs console errors on every episode. See [RECAP](docs/RECAP.md).

### Local models and natural-language tasks

- Native Ollama provider with digest binding, bounded transport, explicit downloads with persisted progress and cancellation, and load/unload controls; an optional LEVI-owned Ollama service with workspace model storage, `OLLAMA_NO_CLOUD`, explicit start/stop and Linux process-identity checks. Default profile: `qwen3.5:4b`. Schema-bound calls run with reasoning off.
- **GPU guardian.** Local-model requests yield to other GPU work by policy (`protect` / `share` / `ignore`, `workbench/models/gpu-policy.json`), wait a quiet window learned from how each workload restarts, unload resident models the moment protected work appears (a cut-off request is a preemption), and resume GPU-blocked runs automatically. `levi agent gpu` / `gpu.status` explain the decision.
- **A small model is fenced in by its schema.** Per-request output schemas allow only the plan's kinds and subtasks and the evidence ids actually shown; intervals must carry an end and an outcome, and an evidence note under the default `full` prompt style; refinements keep the draft's intervals one for one, and boundaries moved beyond the frames shown keep the draft's. Invalid answers keep their valid proposals (for the teacher, or dropped and recorded without one), and their tokens are always settled; an episode with no valid answer at all is set aside and the run goes on (the pilot, or more than 10 % set aside, still blocks). A review can put `final_samples` of its frames on the episode's final state. A temporal interval's subtask can no longer be decoded as null. Local models can run **lean** (`prompt_style: "lean"`: instruction as text plus a frame list, no citations or evidence note to write, LEVI cites the frames and uses the interval's wording as its note), recommended for temporal annotation from paired runs against a bare model call. `workflow.refine: "auto"` skips the refinement pass after a dense coarse pass: faster, but paired runs measured it less accurate than the default `always` (segment F1 0.626 vs 0.641, derived outcome 0.791 vs 0.834), so `always` stays the default and recommendation.
- **Local OpenAI-compatible servers (vLLM).** Provider kind `openai-local` runs a model served by vLLM through the same hardened path as Ollama: narrowed `json_schema` answers with thinking off, compact evidence, request-cost calibration, `max_images` and `image_max_side`, salvage, pause/cancel, natural-language tasks and the `local-vlm` evaluation driver. `fold_system` serves templates without a system role. Binding sets `context_tokens` to the server's `--max-model-len`. The GPU guardian recognises the server a profile points at by its listening socket, and resumes a blocked run only when the GPU is clear for that run's own profile. The guard now also covers every loopback spelling of a local endpoint (`127.0.1.1`, the host name, `[0:…:1]`). Ollama calls now keep `load_seconds`, `prefill_seconds` and `decode_seconds` in their usage.
- **Requests sized to the model.** Compact evidence rows; per-image and per-character token cost learned from the model's metered requests (calibrated once); refinement images fitted to the context window; long episodes refined in batches; an episode whose refinement fits neither keeps its coarse draft (`refinement_skipped`) instead of blocking an unsupervised run; the answer budget sized to the intervals expected; Ollama context overflows reported with their numbers.
- **Optional requests in flight.** A provider profile's `requests_in_flight` (default 1, at most 8) lets a run work on that many episodes at once, one request each, so a server that batches requests (vLLM `--max-num-seqs 2`) decodes one answer while it reads another prompt. A failure, pause or cancel starts no further episode and lets the running ones finish; the pilot stays one episode. Answers can differ in the last digits between runs, so the default stays 1. See [Ollama and local models](docs/OLLAMA.md).
- **A lean learner decodes only what LEVI cannot fill in.** A lean proposal carries `subtask_id`, `start`, `end`, `outcome` and `content` (`kind` only when the plan allows several kinds), and a lean refinement writes `start`, `end` and `outcome` per pinned draft interval; the draft keeps its kind, subtask and wording. LEVI fills the rest before validation, salvaged answers included. Fewer output tokens matter because decoding dominates a local model's time.
- **Faster evidence and GPU checks.** Evidence frames of an episode are read in order instead of one seek per frame (a seek decodes again from the previous keyframe), and the storage budget is measured once per call instead of listing the evidence folder for every frame; the frames are byte-identical to before. The GPU guardian reuses a "free" verdict for the same model servers for 10 s; a busy, cooling or shared verdict is never reused.
- **Natural-language tasks.** `levi agent task new "…"` and a task console in the Workbench (which remembers the viewer's last task across reloads): the local model turns a sentence into a task spec, LEVI checks it against the catalog, a person approves it, and `advance` runs each step up to the next human gate, ending with a token and time report.
- **Teacher supervision and teaching memory.** A scoped external agent can accept, revise or reject each learner phase. Feedback is kept per phase under `datasets/<name>/teaching/` and becomes a note in the dataset's memory. Every local-model prompt carries a bounded brief of that memory, frozen at plan time and never containing the episodes being annotated. Teacher references and grading (`teaching/reference-<task>.json`, `teaching/grades.json`).

### Harness: task closure, cost, memory and self-improvement

- Every finished run is closed exactly once (a service restart closes any that ended unnoticed): a task ledger (`datasets/<name>/tasks/<run>/ledger.json`), a dataset memory of human-committed facts (`workbench/memory/<name>.json`) and deterministic triage.
- **Cost as part of the harness.** One token and time record per run for API, local and external agents (`metered`, `reported`, or LEVI's measured lower bound), with a breakdown and waste signals; per-dataset, per-agent cost profiles feed `plans.estimate` (`local`), `cost.profile` and the next plan. The web UI's own calls are never counted as agent tokens.
- **Self-improvement loop.** Improvement candidates move `proposed → evaluating → qualified → awaiting_authorization → published → observing → retained / rolled_back`; LEVI computes the evaluation on stored evidence, one revision is allowed, a person publishes. Publishable parameters: `evidence.refine_top_k`, `evidence.mosaic_tile_width`. Cost-rise, slow-tool and oversized-response findings are filed automatically.
- `quality.inspect` exposes the structural quality checks to agents; reports are kept per dataset per hour (`reports/quality-<YYYYmmddTHH>.json`), also from the Doctor.
- `evidence.changes` ranks coarse intervals by visual change; with a published `refine_top_k`, `runs.prepare` returns `refine_first` and the in-process runtime refines those windows too. `evidence.read` accepts `images: false`.
- **Built-in knowledge.** Dataset-agnostic rules ship in `levi/knowledge/` (annotation, task interpretation, harness). Every model LEVI runs receives the rules for its job, and external agents get the annotation rules from `workspace.get_context`. Every run closure refreshes the list of local notes that could join them. A person promotes a candidate (`levi agent knowledge promote`, rewriting it to be general) or rejects it. The check refuses text that names episodes or times.
- **Evaluation records.** An agent's committed subtask annotation of a whole dataset writes `eval/<dataset>_agent_<YYYYmmddTHH>_<driver>.md`, where the driver is `external-mcp`, `external-pilot`, `api`, `local-vlm` or `local-vlm-teacher`. The record covers completion, second- and frame-level coverage, semantic richness, structural correctness and agreement with same-content dataset copies, the same measures as a person's recording. It adds efficiency and non-local (external) token accounting.
- **Docs keep up with the code.** `levi docs check` (also run by `levi check` and the tests) lists every capability, `levi agent` command and user-facing setting missing from the docs, every broken relative link and every stale generated section. `levi docs sync` regenerates the capability reference and the knowledge index.
- `reset` now also removes a dataset's teaching phases, cached model answers, tasks, task ledgers, teaching files, memory, improvement candidates and publication receipts.
- CLI: `levi agent task`, `levi agent improvements`, `levi agent memory`, `levi agent knowledge`; `levi docs`; `levi agent disconnect` removes the MCP entry it wrote.

### Agent workbench

- **Recorded signals in the evidence.** The first `evidence.read` page of an episode carries `signals` from its state/action columns (gripper close/open, height turns, still spans, to the frame); `evidence.refine` takes `window_seconds` for a narrower look. Answers dropped fields a reader of times cannot use (`ledger_digest` and `next_offset` on a whole-episode mosaic, the refine policy block, float noise), and `propose_segments` returns counts instead of every remaining episode. Signals are given without interpretation (neither boundaries nor attempts). `evidence.read` takes `episodes: [...]` (up to four whole episodes in one call). Agents stage what they have decided before reading more, in the same turn as the next read, and refine only what a sheet cannot settle.
- **Dense looks at a chosen step, several episodes per call.** `evidence.refine` takes `ranges` (spans watched at `step_seconds`) besides `around_seconds`, and `episodes: {N: {...}}` for up to four episodes per call; dataset adapters gain `sample_frames`. Built-in rule annotation-012: `unknown` is for what the recording does not show, not for what was not looked at.
- **Boundary checks and re-staging.** `evidence.boundaries` shows, per staged episode, one row of frames around every boundary with the plan's start/end definitions; `propose_segments` `replace: true` re-stages an agent's own episode in place (never one a person reviewed). `evidence.refine` is now covered by the plan's media-egress authorization like every other image-returning read.
- **Namespaces: one input, many isolated experiments.** `<dataset>--<namespace>` (`levi namespace create|list|remove`, `GET/POST /api/levi/catalog/{name}/namespaces`) is a catalog entry of its own over the same source folder and view: annotations, runs and the active head, memory, teaching, examples, eval records and cost profiles are separate per namespace, nothing is copied, and namespace notes never become knowledge candidates. Path lookups answer the base dataset; the annotation backend keys its state and sidecars by catalog name.
- **Built-in subtask vocabulary.** Every dataset without its own vocabulary uses LEVI's task-agnostic manipulation vocabulary (`levi/knowledge/subtasks.json`, 23 subtasks: object-transfer phases plus contact skills, each with observable start/end/success, confusions and aliases, from RH20T-P, AgiBot World, BridgeData V2, DROID, EPIC-KITCHENS-100, MimicGen, Rubicon Boundaries). A temporal plan without definitions gets it; annotators add missing subtasks with `new_subtasks` (never a synonym of an existing id or alias), and a committed addition joins the dataset's vocabulary. Plans hold up to 64 definitions. `temporal-annotation` skill @7.
- **DROID test sample.** A workspace LEVI creates draws 500 episodes of the public DROID raw release in the background the first time the core runs (`levi/samples/`): the reference subset script's seeded round-robin across (lab, outcome), metadata + trajectory + non-stereo MP4 only, every file checked by size and MD5, resumable and assembled in a hidden `.partial` folder (the first draw: 11.6 GiB, about 24 MiB per episode; free space is not checked). `levi sample draw` / `POST /api/levi/samples/droid_raw` draws another (`droid_raw_<size>_drawNN`, the workspace's next unused positions of the order, recorded in `_meta/selection.json` — the positions, not the name, identify a draw); `LEVI_DROID_SAMPLE=off` (or `0`/`false`/`no`; an unknown value too) disables the automatic draw. Ctrl-C and `levi sample cancel` stop a draw promptly; cancel refuses a draw in a process it cannot identify, and `--discard` deletes only once the draw stopped. A draw published just before its process stopped, or a sample folder whose ledger was lost, is recorded rather than drawn again. The core resumes a draw left interrupted or failed on the network, at most 3 times. Each listing page and file is one retried request; a refusal or a full disk is not retried.
- **Problems only.** A staging receipt names `problems` for an episode only when its segments break a general rule (`levi/agent/checks.py`: two intervals of one subtask meeting, an `unknown` the next segment settles, never for `other` (annotation-004) -- right 78-90% of the time against a full-dataset reference; a signal-based "two engagements" check, right about half the time, was dropped); guidance no longer asks for a routine boundary check of every episode (measured: 20 checks, one re-staging).
- **Attempts, stated once.** Built-in rule annotation-007 now defines an attempt as one continuous engagement with an object (each its own interval and outcome, a new approach between two, failure when the effector leaves without the object) after manipulation-annotation practice (Rubicon Boundaries, MimicGen, REBOOT, AgiBot World); it replaces the earlier rule that merged repeated attempts. `temporal-annotation` skill @6, `levi-overview` @12.
- **Task-agnostic grading.** `harness/grading` drops the stacking-specific `place_agreement` for `time_accuracy` (share of the reference's annotated time with the same subtask) and `outcome_time_accuracy` (same subtask and outcome); evaluation records show both.

- One capability dispatcher for UI, REST, stdio MCP and CLI; executable plan approval, human pilot gate, budget revision, workflow-specific skills and content-keyed evidence and model reuse.
- The plan form offers what the dataset declares: episodes, cameras and tasks are clicked or dragged; spending limits appear only for a configured model endpoint.
- Evidence follows the approved observation policy, can be read as one labelled contact sheet per page (`layout: "mosaic"`) and refined around unresolved boundaries (`evidence.refine`).
- `runs.list` tells an agent whose turn each run is; `workspace.get_context` orients a first-time agent; **Live activity** streams every call, refusal and artifact path.
- Object masks: `objects.strategy` chooses SAM3 or the agent; `objects.detect` measures candidate regions without a model; `objects.propose` accepts `candidate_id` and links identities by overlap. Masks carry between annotated frames in the viewer, dashed and labelled.
- `changes.rebase`, `runs.abandon`, `levi agent clean` (regenerable files only) and `levi agent reset` (one dataset's agent history).

### Human annotation

### Fixes

- **An external agent annotates a dataset in fewer turns.** Measured against the same task without LEVI, an agent spent its extra tokens on paging and bookkeeping, not on looking: a mosaic page now holds up to 32 frames by default (one call per episode instead of paging by 8); `evidence.refine` answers with a sheet of just the added frames and, past the frame cap, refines what fits and names the rest instead of refusing; `annotations.propose_segments` lets an external agent leave evidence ids to LEVI (it cites the frames it showed inside each interval), uses a success's content as its evidence note, and snaps a boundary within half a frame of the first or last frame. Contact sheets are JPEG and a refinement's frames share one sheet (split past 30 tiles), sampled at the plan's boundary tolerance: PNG sheets of 1–2.4 MB each overflowed an agent's request and silently removed the images it had read. `levi agent call <capability> @-` gives shell-based agents what the MCP bridge gives MCP clients, images included. A capable external agent also works with less ceremony: its plan samples one frame per second on six-column sheets of up to 48 frames (one read per episode), the first read of an episode prepares it (`runs.prepare` optional), `annotations.propose_segments` accepts `segments: {episode: [{start, end, subtask, outcome, description}]}`, mosaic answers list frame times rather than evidence ids (`ids: true` adds them), and the person approving a plan may waive the separate pilot (`require_human_pilot: false`). `changes.edit` takes `episodes` to replace only those episodes, refuses an edit that would silently drop staged episodes, and answers an agent with a receipt. Refused agent calls are now a cost signal (ledger, hints and the evaluation record).
- `other`/`unknown`/`background` are never counted as outside a vocabulary; `supervision.pending` lists only waiting phases unless asked for history; an evaluation record can be written for annotation made outside LEVI (`record.imported`).
- **Nothing LEVI starts outlives it.** SAM3 workers, conversion jobs and Pilot runtimes are recorded in `workbench/processes.json`: a normal service stop terminates their process groups (a SAM3 worker used to keep running on the GPU), and the next start or `levi stop` reclaims the groups a killed service left behind. A process is signalled only after its identity is checked. `levi stop` now waits for the service to exit, and `levi stop --all` also stops LEVI's own Ollama.
- A SAM3 job from the page is stopped past `LEVI_SAM3_TIMEOUT_SECONDS` or after `LEVI_SAM3_STALL_SECONDS` without progress; it had no limit at all.
- Pausing or cancelling a local-model run cuts its request in flight, and Ollama stops generating; the model stays loaded for `LEVI_OLLAMA_KEEP_ALIVE` (default `2m`) after the last request instead of Ollama's 5 minutes.
- **A run's token total can be unlimited** (`budget.max_tokens: null`, or an empty Tokens field in the plan form); natural-language tasks plan without a cap. Each model request still reserves and settles its own context window, and calls and time stay bounded. A full-dataset local-model run no longer hits the old 1,000,000-token ceiling.
- A Pilot session ends, with its Codex/Claude process, when its run finishes or after `LEVI_PILOT_IDLE_SECONDS` without a message, instead of waiting out its whole duration budget.
- Re-annotating an episode no longer stacks a second run's segments on the first; agent-published segments are replaced, human-edited ones kept.
- Published segments keep their subtask, outcome, attempt and uncertainty (previously only text and times survived commit).
- Agent tokens were overstated when web-UI calls were counted as agent calls; propose, refine and mosaic answers no longer echo whole change sets or ledger rows.
- Call ids were shared by every call in the same minute; `reset` could delete records before files and leave orphans; a job thread could outlive its test and write into the real workspace.
- The GPU guard treated Ollama's own `llama-server` as a foreign process; the local-model transport timed out while a model was still loading.
- Signing in to Hugging Face no longer breaks local datasets; object masks draw again; errors name the evidence or subtask they reject.
- Tests wrote learned request costs into the live workspace (`models/request-cost/ollama.json`); GPU history, request costs and evaluation records are now isolated in every test.
- Finishing a natural-language task whose quality step had already run failed with `UnboundLocalError`.
- Chinese uncertainty notes were filed under `other`; they are now classified like English ones.
- Clicking a segment on the episode timeline (subtask, advantage run, band) now seeks to its exact time; it used to snap to the whole second, up to 9 frames early at 10 fps. Shared links with `?t=` still seek on open.
- A namespace of a raw capture opens as soon as its base view is ready; the dataset list used to show it as still building and never linked it.
- The `Dockerfile` no longer copies a `public/` folder the repository does not have, which stopped `docker build` at that step. The image has still not been built.
