## 问题与现有边界

子任务规划器校验对象并渲染策略文本，不证明训练覆盖范围。`levi/automatic/subtask_loop.py` 提供 `INSTRUCTION_TEMPLATES`、`render`、`parse_plan` 和 `Subtask.instruction`。模型的 `suggested` 不是实际下发指令。模板说法不一致只说明值得调查，不能证明策略不具备能力。

`levi/domain/aeri.py::JobDeployment` 冻结 config、checkpoint ID 和目录；`Checkpoint.sha256` 可空。`levi/automatic/fr3_bridge.py::check_identity` 比较 config 与位置，不验证权重内容。`levi/automatic/cli.py` 在 subtask 模式只冻结 forward deployment；reverse 使用同一策略，不引用不存在的 reset deployment。

hub 既有 `programs/levi2/MODEL-REGISTRY-AND-RUNRECORD-DESIGN.md` 将登记表定义为引用层，首版记录中的 `sha.verified` 仍为空。目录、fingerprint、声明的校验和或 `registry_sha` 都不是权重身份的可信认证。`programs/levi2/NATIVE-HARVEST-20261018.md` 的“后续设计审查与开发范围”要求先具备生产者、摘要规范、来源与消费者，才实现此功能。这些 hub 路径是内部设计来源，不是产品依赖。

## 责任与信任

| 角色 | 未来责任 | 当前状态 |
| --- | --- | --- |
| 权重所有者/导出者 | 为交付策略生成完整、不可变的文件清单与生效推理配置 | 本契约尚无获准生产者 |
| 训练所有者 | 导出精确指令文本、稳定来源条目 ID、来源修订以及与该权重的关联 | 尚无经审查声明 |
| 获授权验证者 | 验证文件内容、依赖完整性、来源权限和指令来源，签发有限范围证明 | 尚无获准验证器或信任根政策 |
| 既有登记层 | 保存已接受证据的引用与验证状态，不把声明校验和升级为 verified | 只有既有设计/首版，不在此恢复任务 |
| 比较消费者 | 读取被接受的不可变输入，比较实际渲染文本，不授权执行 | 下文提议，尚未实现 |

所有者声明与训练清单导出属于不同来源类别，均不证明任务成功、可达性或安全。实验成功/失败不能自动生成声明条目；不能自动读取训练数据、冻结评测内容或用户配置补齐声明。

哈希证明内容相同，不证明签发者身份。验证证明必须有独立建立的签发者身份和完整性保护：用已批准信任根验证签名，或采用明确批准、带不可变产物引用的认证发布/审查机制。声明内嵌的自签名密钥、`verified=true`、作者名字、Git commit ID 或注册表摘要本身都不够。信任根选择、撤销与认证发布仍是未解决前提；本设计不创建密钥或签名服务。没有这些前提，即使摘要匹配也返回 unknown。本文不声称证据“不可伪造”；真实性取决于获准机制及其威胁模型。

## 拟议的版本化证据契约

以下名称是设计草案，不是已登记 schema。

- 权重清单 `levi.policy_artifact_manifest.v1`：artifact ID、格式、完整文件表（`relative_path`、`size_bytes`、`sha256`）和显式依赖清单引用。包含全部权重分片、模型配置、实际使用的 tokenizer/词表、归一化统计及影响推理的输入输出变换资源。无法解释的缺失依赖使验证不完整。
- 生效配置 `levi.policy_inference_config.v1`：服务实现修订与依赖/环境锁摘要；解析后的模型配置、归一化和变换引用、动作布局/时域及影响行为的推理参数。包含生效默认值，不只记录命令行覆盖。排除端口、日志路径、时间戳和秘密。服务实现无法枚举的生效参数标为覆盖不完整，不猜测。
- 指令声明 `levi.policy_instruction_declaration.v1`：声明 ID/修订；权重清单摘要；生效配置摘要；来源类别（`training_manifest` 或 `owner_declaration`）；不可变来源 ID/修订/摘要；签发者引用；条目（`exact_text`、`source_entry_id`）。只说明该文本被声明用于该身份，不暗含清单完整性，不引入黑名单。
- 验证证明 `levi.policy_declaration_attestation.v1`：上述所有输入的精确摘要、验证器实现/修订、经认证签发者引用、验证流程/证据引用、覆盖限制、验证时间及有效期/撤销政策引用。验证不仅检查文件，还要检查指令与权重的关联。声明生产者不能靠附上该对象就自我认证。

未来身份绑定是经过验证的“权重清单摘要＋生效配置摘要”，config/checkpoint ID 用于诊断。显示名与目录不是身份。提供的绑定必须与运行冻结策略核对；任意声明和证明彼此匹配，并不足够。

### 摘要规范草案

每个 JSON 契约对规范化 payload 字节求哈希，排除分离签名与外部摘要字段。规范化之前拒绝重复键、未知字段、非有限数字和 schema 非法值。拟采用 RFC 8785 规范 JSON、UTF-8、无 BOM/末尾换行；payload 前加版本域前缀 `schema_id + "\n"`。具体实现和跨语言参考向量须批准后才能使用；本文不声称这已是 LEVI 的既有标准。

清单路径使用相对 POSIX 路径：拒绝绝对路径、空路径分量、`.`/`..`、反斜杠和重复路径；按路径原始 UTF-8 字节排序。首版拒绝符号链接，不跟随链接。权重按原始文件字节计算摘要。外部/基座资源必须通过获准目录内、独立验证的不可变清单引用；引用缺失或可变就标验证不完整。实际权重核验是另行授权、协调资源的作业，比较过程不扫描权重。

指令原样保留：不转大小写、不做 Unicode 归一化、不去前后空白、不压缩空格、不匹配同义词、不删颜色词。JSON 转义可规范化，但解码后的字符串不改写。来源导出若改变说法，必须显式保留转换来源，不能冒充训练原句。摘要规范变化需要新 schema 版本和新证明，不静默重新解释旧哈希。

## 实际拟议消费者与结果

首个消费者是在既有 AERI 检查/分析流程中显式调用的离线报告，不先新增无人调用的通用库。它比较保存计划中成功解析的子任务、冻结 forward deployment 和已接受登记证据。拟放在 AERI check/analysis 旁的只读子命令中，显式提供运行/计划与声明引用。命令名称及登记层接线仍待定，不能对外声称已有可调用命令。

运行前的作业检查无法检查尚未生成的 VLM 计划，只能报告声明可用性和身份绑定。精确文本比较首先适用于保存的计划；接入实时规划是另一次独立审查变更。因此当前拟定首个消费者是给人看的离线报告，不是下发守卫。

历史计划必须保留原记录中的实际下发指令及其运行/片段/journal 来源，并记录解析器/模板修订或冻结模板摘要。用当前 `INSTRUCTION_TEMPLATES` 重解析模型 JSON 可能生成不同文本，不能把重建文本称为历史实际指令。有原始渲染器时应按冻结版本核对记录文本；缺原始来源或渲染器版本就返回 unknown。当前版本重渲染只能单列为假设比较，不能替代原指令。

未来纯比较函数接收经验证的 `Subtask`、冻结策略身份、登记验证器给出的已接受验证结果及不可变声明证据，不接受调用方随手提供的布尔值作为认证证明。函数不读文件、不联网、不调用模型。取得该验证结果的可信适配层是消费者的必要组成部分，不能省略。

逐项结果：index、实际 `instruction`、`match: declared|unknown`、`reason_code`、匹配来源条目 ID 和证据摘要。报告字段：绑定状态（`matched|missing|unverified|mismatch|revoked`）、解析结果、声明修订/摘要、来源类别与引用，以及不可覆盖的 `execution_authorized: false`。declared 只表示文本精确存在于与已验证冻结身份绑定、来源认证过的声明中，绝不表示训练成功、支持、安全或可执行。

缺声明、缺失/不完整验证、不支持的 schema、过期/撤销证据、摘要不符和文本未列出均返回带原因的 unknown。畸形输入生成 invalid-input 报告，不判策略能力。身份绑定不通过时不返回任何正面成员匹配结果。不改写计划、不改变重试次数、不替换目标。

只有 reverse 成功解析后的空计划可报告 `no_steps`，这不证明场景已恢复或能力可用。forward 空计划拒绝、畸形 JSON 和解析失败必须保留为 parse error，不能转换成 no_steps。subtask 模式 reverse 始终复用冻结 forward 策略身份。报告不产生动作、标签、复位成功或恢复命令。

## 验收矩阵与实现前提

| 情况 | 未来要求 |
| --- | --- |
| 实际渲染文本精确匹配，冻结身份已验证，来源认证有效 | declared 附来源，execution_authorized 仍为 false |
| 只有模型 suggested 匹配 | 实际下发文本仍 unknown |
| 动词/颜色/冠词/空白/Unicode 写法变化 | unknown，不改写 |
| 缺生产者、验证器、信任根或来源关联 | unknown，指出缺少的前提 |
| 同目录但分片/归一化/变换/配置变化 | mismatch 或 unverified，不返回 declared |
| 提供身份不同于运行冻结身份 | 即使声明与证明彼此一致也 mismatch |
| 自称 verified 或内嵌自签名密钥 | 不接受为验证证据 |
| 重复字段/文件/指令、转义歧义、符号链接 | invalid input，不扫描或遍历 |
| reverse 成功解析为空 | no_steps，不是 restored |
| forward 空计划或畸形计划 | 保留原解析拒绝 |
| reverse 子任务只存在 forward deployment | 使用 forward 身份，不伪造 reset 身份 |
| 未知 schema/摘要版本、过期/撤销证明 | unknown，不推断迁移 |
| 来源是所有者声明而非训练导出 | 保留 owner_declaration，不升级 |
| 重复比较 | 输出确定、输入不变，无 I/O、标签或控制副作用 |

实现前须：批准生产者/验证者责任与认证机制；与 MODELREG 所有者明确摘要覆盖和参考向量，但不恢复其暂停任务；取得明确获准的样例声明和已验证权重绑定；固定离线报告调用契约与维护责任；独立审查合成验收用例。本设计不授权读取真实权重或训练数据。后续运行接线和真机验证另行审查/授权。

收益是可追溯地指出缺少声明依据的指令。成本是权重/配置/模板变化时维护证明、来源与撤销状态，并验证依赖覆盖。生产者与消费者适配层缺失期间，保留设计，不新建第二套注册表，不实现接受伪造 verified 的模块。既有逆向能力和模板说法 issue 保持开放；声明匹配不能替代措辞成对实验。
